# Ver.32 動作確認結果

確認日: 2026-09-10

対象: ローカル版 Ver.32 / 内部更新番号 32.0

確認環境: Windows 版 Microsoft Edge（390 × 844 のスマートフォン相当表示）、Supabase SQL Editor

## 基本定休日

| No. | 確認項目 | 結果 | 確認内容 |
|---:|---|---|---|
| 1 | 新規店舗に定休日を登録 | 成功 | 新規店舗と同時に日・水を保存し、localStorageへ反映 |

| 5 | 今日が基本定休日ならGPS候補に表示 | 成功 | 「本日は基本定休日」の完全一致を確認 |
| 6 | 定休日でも店舗を選択 | 成功 | 定休日表示中の候補から来店クイック画面を表示 |
| 7 | 定休日以外を営業中と断定しない | 成功 | 営業中表示を追加していないことを確認 |
| 8 | 日付・タイムゾーンの曜日ずれ | 成功 | `Date#getDay()` と端末の Asia/Tokyo を使用することを確認 |

| 10 | バックアップ・復元で定休日が残る | 成功 | 日・木の複数曜日をJSONへ保存し、別ブラウザ状態へ復元 |

## PWA・オフライン

- Service Workerキャッシュ `shochu-keep-ledger-v32-0` を確認。
- `app.js?v=32.0` と日本語OCR学習データがキャッシュ済みであることを確認。
- 通信を切った状態でボトルとラベル画像を保存し、オフライン再読み込み後もVer.32、ボトル、画像が残ることを確認。

## Supabase

- `stores.closed_weekdays smallint[] not null default '{}'` を本番へ追加。
- 値を0〜6に制限するCHECK制約を追加。
- 既存店舗は空配列のままで、既存データは変更なし。
- `stores_owner_access` を含む既存5テーブルのRLSは変更なし。
- Ver.28 `get_shochu_keep_reference` は変更なし。authenticated相当の利用者で本人店舗4件、別利用者店舗0件、参照RPC 4件を確認。

## 実機未確認事項

- 実際のiPhone Safari / Android Chromeでのカメラ起動、撮影、回転情報、ファイル選択UI。
- 認証済みスマートフォンからの定休日とラベル画像のSupabase実往復。
- 2台の認証済み実機による競合通知とクラウド再読み込み。

撮影後の切り抜きは、スマートフォンごとのポインター操作、回転情報、メモリ負荷を今回の実機で検証できず、写真保存フローの安全性を優先して見送った。
