## RLS・権限

5テーブルすべてRLS有効（FORCEではない）。各PolicyはALL、roles authenticated、USING/WITH CHECKとも(select auth.uid())=user_id。

| テーブル | Policy |
|---|---|
| stores | stores_owner_access |
| bottles | bottles_owner_access |
| store_visits | store_visits_owner_access |
| remaining_updates | remaining_updates_owner_access |
| brand_labels | brand_labels_owner_access |

各テーブルで他人のテスト行のSELECT/UPDATE/DELETEは0件。所有者偽装INSERTも拒否。anon/PUBLICへのテーブル権限なし。authenticatedはCRUDに加えTRUNCATE/REFERENCES/TRIGGER権限も持つ。TRUNCATEはRLSの対象外だが、現行Data APIからの直接実行経路は確認していない。これを安全性の完全保証とはせず、共有DBの最小権限見直し候補として残す。
