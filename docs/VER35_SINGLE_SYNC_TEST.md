## 一時ガード

- **一時公開版はフラグ不要・起動時から強制有効。** `SINGLE_SYNC_TEST_RELEASE = true` のまま、データ読込・イベント登録・Auth生成より前に検証停止ラッチを作る。恒久仕様への採用ではなく、通常版への復帰は別途承認後に行う。
- キー：`shochu-keep-ledger-single-sync-test-v1`。URLを変更しても停止する。使用済みのラッチを起動時に初期化しない。
- 表示：`Ver.35 sync-test（一時検証版）`。JS参照：`app.js?v=35.0-sync-test-1`。SWキャッシュ：`shochu-keep-ledger-v35-sync-test-1`。SW登録のupdateViaCacheはnone。manifest/start_url/アプリIDは維持。
- 起動・ログイン・online・visibilitychange・保存後の予約・直接の通常同期を停止。クラウド読込/初回移行も停止。競合時の自動復元をしない。
- 専用ボタンでのみ開始。Web Locksで同一オリジンの更新済みタブ間を排他し、最初の通信前に実行権を消費・保存する。連打、再読込、例外、通信断、途中終了で実行権を復活させない。
- Storage保存またはWeb Locksが使えなければ実行しない。中断したrunning状態からの自動再試行もしない。
- 「1回」は既存同期処理1サイクル（複数のHTTP要求）を意味し、DB全体の単一トランザクションではない。失敗時に一部書込みが完了する可能性はあるため、自動ロールバックせず停止・調査する。
- 試験中の操作変更を抑止。スマホ1台・他タブ/他アプリからの変更なしで実行する。旧コードの開いたタブや他ブラウザ、サイトデータ消去まではこのガードでは制御できない。

## 書込み前の停止条件

- ログイン/既存同期設定/オンライン条件が不足。
- 店舗/ボトル/ラベルの比較値に相違、残量変更・来店削除・ラベル更新の未送信キューがある。
- ボトルの実保存列も確認し、表示用の容量補完で隠れるNULL/0容量等の更新も事前停止する。
- 来店日の削除予定、または2件以上の追加予定がある。
- クラウド競合、または確認開始後に端末状態が変化。

今回はデータ復旧を含めないため保守的に制限する。停止した場合、既存競合を強制採用したり、再度実行できるようにラッチを消してはいけない。
